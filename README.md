# 中国帝王寿命数据库 · China Imperial Longevity Database

**▶ 在线访问：<https://no-macaroon1670.github.io/ImperialLongevity/>**

对标欧洲研究 *Survival and longevity of European rulers* 的中国版本。收录秦至清共 **382 位**君主
（含三国、十六国、南北朝、五代十国、辽金夏与大理等并立政权），以生存分析回答：

> 帝王的寿命，主要由医疗水平决定，还是由政治制度与权力风险决定？

纯静态单页应用，无外部依赖、无构建步骤。Kaplan–Meier、Log-rank、Cox 比例风险、
Aalen–Johansen 竞争风险、Mann–Whitney、Spearman、自助法——全部在浏览器内以 JavaScript 现算。

## 运行

```bash
python -m http.server 4190 --directory imperial-longevity
```

或在 Claude Code 中：`preview_start { name: "imperial-longevity" }`（已写入 `.claude/launch.json`）。

## 数据模型

每条记录的紧凑短键（见 `js/schema.js` 顶部注释）：

| 键 | 含义 | 键 | 含义 |
|---|---|---|---|
| `n` `t` `p` | 姓名 / 庙号通称 / 谥号 | `c` | 死因编码 |
| `d` `e` `tc` | 朝代 / 民族 / 称号类别 | `o` | political_order |
| `b` `x` `xc` | 生 / 卒 / 末次可考日期（删失） | `f` `l` | 开国 / 亡国 |
| `a` `r` `z` | 登基 / 实际掌权始 / 退位 | `u` | 大一统属性覆盖 |
| `rg` | 多次在位区间 | `F` | 标志位串 |
| `cs` `ch` | 后妃数 / 子女数 | `no` | 备注 |

**死因编码**：`0` 自然 · `1` 疾病 · `2` 被杀 · `3` 战死 · `4` 自杀 · `5` 不明 ·
`6` 意外事故（本库对需求文档 0–5 的显式扩展，如北齐孝昭帝坠马）。
`violent_death` 由编码派生：2/3/4 → 1，0/1/6 → 0，5 → `null`（不强行归类）。

**标志位**（`F` 串中出现该字母即为 1）：
`w` 内战 · `u` 政变 · `p` 被废黜 · `k` 首都陷落 · `W` 对外战争 ·
`A` 服丹药 · `i` 慢性疾病 · `L` 酗酒 · `O` 肥胖 · `D` 死因存疑 · `N` 名义君主 · `G` 女性。

> **关键约定**：所有标志位取 `0` 一律表示**「无明确史料记载」**，而非「确证不存在」。
> 这是本库最容易被误读的地方，UI 与本文都反复声明。

**入库标准**：持有皇帝、天王、大汗名号者全部收录；仅称「王」而政权独立者（吴越钱氏、
楚马氏、南平高氏、吴杨氏、北凉沮渠氏）收录并以 `tc` 标注，默认过滤器**不含**这一类；
名义君主（如孺子婴，实未即皇帝位）收录但默认排除。这些边界都是可切换的开关，
而不是写死的判断——因为「谁算皇帝」本身会改变结论。

**DSI**（Dynasty Stability Index）＝ 王朝总年数 ÷ 皇帝人数。西汉 210/15 ≈ 14，北齐 28/6 ≈ 4.7。

**大一统**取严格定义（秦、汉、西晋、隋、唐、元、明、清）；北宋另设宽松开关。
元的前四位大汗（1206–1259）与清入关前的努尔哈赤、皇太极虽属元、清两朝，
其在位时中国并未统一，以 `u:0` 逐帝覆盖。

## 时间轴的三种读法

**纵向**（`#timeline`）：一行一位皇帝，325 行纵向铺开，细线＝寿命、粗块＝在位。看的是「个体」。

**竖向河流**（`#panorama`，窄屏默认）：时间自上而下流，河宽恒定、按当时并存的政权数均分——
一股是天下一统，分裂时河面裂成数股各自着色的分叉，重新统一时再合流。看的是「分裂的形状」。
四个设计决定：

- **河宽只编码政权数，不编码疆域。** 本库没有疆域或人口数据，若让分叉宽窄表示「谁更大」，
  那是在画我们并不掌握的东西。理想的调节量其实是各政权的真实疆域面积（河宽即国力，
  且自带总量上限），但那需要逐年疆域数据，且元、清这类跨界政权难以归一——不可行。
  代价是三年的割据小国与盛唐同宽，真实规模见点按详情与数据表。
- **法统继承与承平回归。** SUCCESSION 后继**原地**整段接管前身的车道——继位是
  改名，不是搬家（北宋亡，南宋接其全部车道；此前南宋按新丁只挤到 1 条，与辽金
  大理等宽，正统主线看着突兀）。前身亡后隔几年才建号、其间无空窗清场的
  （西晋 316 亡、东晋 317 立而汉赵仍在场），空置车道记着原主（freedBy），后继凭此认领。
  格局未变的承平时段里，低于公平份额者每约 24 年向份额缓步靠拢一条：沿相邻链找
  最近的超额者整链平移（北宋的份额曾压在大理手里、隔着辽，单看两邻永远转不过去）；
  只救济饥饿者，征服所得在无人饥饿时不没收——元并金的水不会平白还给南宋。
- **车道扫掠有状态：宽度只在四种时刻变化。** 新政权挤入（不得不让）、征服承接
  （灭国的水立刻归征服者——前秦并前燕实测当场 91→141px，那是史实）、空置满 16 年
  后的缓回收、以及天下一统。其余时候一律保持现状：政权死后其车道先空置成**留白**，
  邻居不立刻胀开——快变期宁可留白，不要急弯。实测东晋在桓楚生灭（403–404）、
  南燕生灭（398–410）间宽度纹丝不动（93px 稳定到底），此前每次生灭全体幸存者
  跟着起伏。满员峰值的极端交接处挤不进时**链式挪位**（见下），不再整片重排。
- **在场的河优先保住自己的车道（惯性）。** 用户诊断出的系统病根：继位者曾被当作
  新丁按全局次序另寻插入口——北燕（407 年立，燕家序在南燕之后）落到南燕右侧的
  空位，后燕的河道只好弯过南燕头顶去接，承统窄颈横跨第三条河的河面；新丁挤不进时
  更曾整片退回标准分配——555 年西梁一入场，梁骤失两车道、西魏北齐全体平移，
  同屏所有河道为一个新丁瞬间重排。现在：继位**原地改名**（北燕接后燕原车道直线
  贯通，南燕无恙）；新丁先吃身旁空位，两邻让无可让时向最近的**松动处**（空车道，
  或宽逾一条的河道）链式挪位——途中河道只侧移一条车道、宽度次序不变
  （西梁入场实测只有西魏让出一条、北齐侧移一条，梁保全宽直到亡于陈）。
- **河宽切成 C 条固定车道，按整数分配。** C＝全图并存峰值（当前默认筛选恰为 7，
  与用户手绘草案的七条不谋而合）。任一时刻的 n 条河道各分得整数条车道：
  一统独占 7/7，两雄并立 4/3（南北朝实测 463/346px），三分 3/2/2，依次类推，
  多出的车道自左先分（左侧是正统主线）。要点在于**车道边界是全图固定的网格**：
  政权生灭只转让整数条车道，未被转让的边界纹丝不动——这是河流「更直」的来源，
  也消掉了此前按比例摊缝时远端河道跟着呼吸的毛病（曾对容量窗口方案实测：
  冉魏立国竟使东晋移位 34px）。位移大的改道（统一、大分裂）把过渡窗自动拉长至
  三倍，不出现近乎直角的急弯；河道另有 ±2px 的**确定性蜿蜒**（相位取政权名散列，
  不用随机数，重绘逐像素稳定），免得大一统的长段读成矩形。
- **交棒是三角洲，不是沙漏。** 禅让的两端常差一个月（献帝逊位 220-11、曹丕受禅
  220-12），不在同一切点，微腰触发不了——东汉曾被深掐成 3px 细流，随后魏在一个
  0.34 年的微段里被要求瞬间涨满（平顶急弯）。现按**微段桥接**处理：短于 1.5 年的段
  不作过渡目标，由前一稳定段直接过渡到下一稳定段（微段布局仍供点查；含独有政权者
  与合计超 4 年者不桥接，中华帝国的 83 天因此保得住）。汉魏交替实测为一个 142px 的
  **共享河口**：东汉十四年缓收进河口、魏四年缓开出河口、蜀同步扇出——river delta。
  河口宽度也从六成放宽到七成五：交替应读作「同一条河换了名字」，不是「塌缩重生」。
- **连续性三级，断流只留给真正的终结。** 由已有数据系统性推导：有 SUCCESSION 且无
  空窗＝75% 宽河口（禅让改名）；有 SUCCESSION 且隔着空窗（秦亡至汉兴隔楚汉之争五年、
  平帝崩至王莽代汉隔居摄三年）＝10px 级细颈**贯穿空窗不断流**——法统如一线悬丝穿过
  乱世，空窗仍由四周留白与细颈之窄读出（空窗段 ≤16 年时桥接进过渡窗，承统窄颈才有
  机会跨窗触发）；无承继关系＝收束成尖加留白，断流留给真正断绝的世系。
  实测秦→汉与汉→新均为共用的 20px 连续细颈，不再前朝收尖、后朝再起尖地两尖相抵。
- **出生按全局总序落位，此后位置有惯性 ⇒ 河道永不交叉。** 新政权按固定排序键落座；
  落座后没有任何机制会让两条并存的河道互换左右（继位原地改名、挤入只侧移不越位），
  共存者次序一经确定终生不变，故不可能相交。正统序列与北方主线各按法统连线；其余政权沿
  「排序改判 → 法统相承 → 裂土分出」上溯到**谱系家长**归堆——赵家
  （汉赵→后赵→冉魏→前秦→后秦→胡夏）、燕家、凉家、五代各家连成相邻块，家族内按起年排。
  初版让无 SUCCESSION 者自成一根：冉魏（350 年立）被排到最右、横插进十六国中央，
  整片河面为它挪位。个别政权疆土与血统不一致（西燕裂自前秦而血统属燕），
  由 `dynasties.js` 的 `ORDER_HINT` 手工改判——发现排错边加一行即可。
  `ORDER_HINT` 亦接受**数值**（直接指定排序年），用于外置无前身的长寿孤立政权：
  大理（937–1254）按起年会卡在十国中段，而十国先后亡入宋，汇流线全得从它身下穿；
  外置到最右后它在同一条车道待完一生（实测 960/1100/1250 三探针位置纹丝不动），
  先亡邻居的进出通道不再受遮挡。
- **称帝前掌权期不占槽位。** 泳道的带首含掌权期（半高段需要它），照搬到河流会让孙权
  自 200 年就占满一个槽——东汉最后二十年被挤出满宽、曹魏蜀汉的分叉凭空悬置。
  现在槽位只从首位君主实际在位起算：东汉 219 满宽 → 魏受禅满宽一瞬 → 蜀（221）吴（229）
  渐次分出，吴的空槽提前预留、其至精确落入。掌权期本就不计入任何统计，也不该占河面。
  政权消失时右邻左移即「合流」，新政权插入时右邻右让即「分叉」——图上所有分合都只是
  排序与惯性规则的结果。（早期版本的已知残留「远端河道跟着呼吸、冉魏立国时东晋移位
  34px」已由固定车道网格与惯性规则先后解决——当初记为下一步的 storyline 式有状态布局，
  如今即上文的车道扫掠三则。）
- **亡国是汇流，不是蒸发。** 政权终结时其疆土并入谁家、建立时从谁家裂出，都是已知史实，
  记在 `dynasties.js` 的 `MERGED_INTO` / `SPRANG_FROM` 两个映射里（逐条附年份与依据）。
  河道收束时弯向吞并者的河岸并没入其君主色块之下（北齐亡于北周、陈并于隋、南宋亡于元、
  前燕亡于前秦…），新河道的细流自母体的河岸涌出（清起于叛明的后金、金起于叛辽的完颜部…）。
  与 SUCCESSION 的分工：SUCCESSION 记禅让式法统相承（画成变色窄颈），此二表记武力吞并与
  裂土自立。绘制端有一道**相邻性判定**：吞并者与亡者之间隔着第三条河道时弯过去必然横穿
  别人（河道永不交叉是硬约束），此时改画一条半透明的**穿流带**——压在途经河道的君主色块
  之下、只在底色间隐约可见，点选该政权即点亮其河床与穿流带（sankey 半透明 ribbon 同理）。
  当前 26 条：蜀亡入魏隔着吴（孙权 200 年已掌权，故吴排位在蜀之前）、西夏亡入元隔着金、
  西晋亡入汉赵隔着成汉…。五处标志性汇流经数值验证精确落岸（误差 ≤1px）。
  同切点禅让的窄颈放宽到六成（曾为两成）：宋→齐、五代五朝本是同一政权换了家姓，
  深掐成细颈会把「延续」错画成「崩解」——崩解式收束只属于有空窗的更迭
  （西汉亡至新莽立、秦亡至汉兴间的楚汉之争），那由细流与空档自然呈现。
- **改道是长弯，交替处不断流。** 初版在每个政权起讫点瞬间重分河宽、只留 10px 圆角，
  整张图读起来像阶梯，密集期尽是毛刺。现按 alluvial diagram 的画法重做：每次改道摊开成
  约 ±46px 的过渡区（不超过邻段一半，保证过渡窗互不相交），用 smoothstep 缓动采样成折线。
  新政权自**一线细流**（3.2px）张开、亡者**收束成细流**而不掐断成零宽的尖——收到零会在
  法统交替处出现「X 形掐断」，河面像消失了一瞬；d3-sankey 的 `linkMinWidth` 是同一惯例。
  **法统相承且同一切点交棒者（汉→新、唐→后梁、后周→北宋…）共用一个「颈缩」盒**：
  前朝收进它、新朝从它张开，交替处是一段变色的窄颈而非两个背对背的尖——ggalluvial 把承续
  画成一条连续 ribbon，同理。细流放在按全局次序它本应插入的缝隙中点，于是河面在政权建立
  前数年就开始让位——分叉是预告出来的。这是排版的提前量，不是史实的提前：淡色河床可早于
  建国张开，君主色块的起讫始终是真实日期。所有河道在同一过渡窗内做同一插值，而两个不重叠
  分割的凸组合仍是不重叠分割——这是长弯不打架的数学保证。河道间另留随河宽自适应的
  5–9px 底色缝（参照 alluvial 诸例溪流间的留白）。绘制分四层（河床→掌权条→君主段→朝代名），
  预告细流只会显现在缝隙与河床里，不会浮在邻河的君主色块之上。
- **不套滚动容器。** 竖向内容再嵌一层竖向滚动是经典滚动陷阱：手指落在容器上，页面像卡住了。
  河流直接交给页面滚动，全页只有一个滚动器，陷阱从根上不存在。代价是这一节长达两万余像素，
  故窄屏配顶／底两条固定条：既是上一节／下一节跳转，也是「一定不会点中什么」的**安全起滑区**——
  除箭头外刻意留空，不放任何其他功能。
- **点选而非悬停。** 触屏没有悬停。点中某位君主即高亮该段、其余压暗，详情进底部固定卡片；
  点空白处取消。君主名在河道内**竖排**（汉字的本来排法）。非正常死亡改为**河道右缘的红色刻痕**——
  初版横贯全河道，在五代十国这类短祚扎堆的年代叠成一片红白横纹；君主段间的缝也改按像素给
  （1.1px）而非按年给，密集期不再放大成一屏横纹。

视图挂在 window 上的滚动监听与挂在 body 上的固定卡片，都收进 `__riverCleanup` 钩子，
在切换视图或重新筛选时撤掉——否则每次筛选都会累积一个引用死 DOM 的监听器。
全宽出血的宽度不用 `100vw`（含竖向滚动条宽度，会挤出 8px 页面级横滚），
而由 JS 把 `clientWidth` 写进 `--vw-safe`。

**横向泳道**（`#panorama`，宽屏默认）：朝代做成横向长带，皇帝做成带内分段，横向滚动即时间流逝。看的是「同一时刻有几个政权在运转」。三个设计决定：

- **最上一行为正统序列专用。** 23 朝——秦、西汉、新、东汉、曹魏、西晋、东晋、宋齐梁陈、
  隋、唐、后梁后唐后晋后汉后周、北宋、南宋、元、明、清——独占第一行，不参与泳道回收，
  任何割据政权都不会挤进来，于是它自成一条贯通两千年的主线；其余政权一律平等地排在下方，不含褒贬。

  **交替处的并立用上下半轨表示。** 实测正统线上最多两朝同时并存，故交替期上一朝居上半轨、
  下一朝居下半轨，其余时段各自占满整轨；并立区间另加 45° 斜纹底衬（此处纹理编码的是
  「正统未定」这一状态，非装饰）。共七处：陈与隋并立 **8 年**、南宋与元 **73 年**、
  明与清 **28 年**，以及隋唐、后梁后唐、后唐后晋、元明四处不足一年的交接。
  这些并立不是数据瑕疵——正统归属本来就要到那一段结束才由后世追认，图上如实画出比抹平更诚实。

  **这是史观选择，不是史实。** 采用《资治通鉴》以降的传统正统观（三国承曹魏、南北朝承南朝、
  五代承中原五朝）；而北魏、辽、金、西夏在各自时代同样自居正统，今人亦多有以北朝为隋唐所自出者。
  界面与 `js/dynasties.js` 的 `ORTHODOX` 注释都明确声明了这一点。

- **第二行优先安排「北方政权主线」。** 中国史上有两段是南北法统长期并行，而正统行都取南方为正朔，
  北方政权便被挤到下方各行，对峙关系反倒读不出来：

  | 时段 | 北方主线 | 收束 |
  |---|---|---|
  | 386–581 | 北魏 → 西魏 → 北周 | 581 年北周禅隋，并入第一行 |
  | 916–1234 | 辽 → 金 | 元既已入正统行，亦并于其中 |

  两次都以「并入第一行」收束，恰好呈现北方政权最终统合天下的节奏。线内交替若两朝并存
  （辽金并立十年），沿用与正统行**相同的上下半轨画法**，使全图只有一套视觉语法。
  第二行**并不独占**——两段线合计约 500 年，其余时段照常参与回收。
  西夏（1038–1227）与辽、金三方并立，不入此线，平等排在下方。

  不足半年的交接（北魏→西魏仅十八日）照样切分上下半轨以免两带真的重叠，但不再加斜纹底衬——
  那只是月度精度造成的数日重叠，画出来是一道看不见的窄条。

  为此泳道占用改记为**区间表**而非单一末端值：正统行与北朝线要先于其余政权落座，
  落座顺序不再与时间顺序一致，只有区间表才能让后来者准确填进它们之间的空当。
  这一改动顺带把「仅称王者」情形的泳道数从 10 压到 9。

- **泳道可回收，且按法统接续排布。** 一条泳道不归属任何朝代——某朝终结后该行即被后来开始的
  政权接管，于是任一时刻被占用的行数就等于当时并存的政权数。默认筛选下 61 个政权装进 **7 行**；
  放开「仅称王者」后 65 个政权装进 **9 行**，恰好容纳中国史上最挤的 937 年
  （吴、楚、吴越、闽、辽、南汉、后唐、南平、后蜀、后晋、南唐同时并存）。

  纯粹的「首次适配」谁先空出来就给谁，会把前蜀与后蜀分到两行、西魏与北周各据一方、
  五代的中原正统线打散到五条泳道上——同一条法统在图上根本读不出来。因此在装箱之上加了
  一层偏好（`SUCCESSION`，见 `js/dynasties.js`）：后继政权优先落在前身那一行。
  于是秦→西汉→新→东汉→曹魏→西晋→东晋→刘宋→南齐→梁→陈→唐→后梁 连成一条，
  东魏→北齐、西魏→北周→隋 各自成线，前蜀→后蜀、吴→南唐、后晋→后汉→后周→北宋→南宋 亦然。
  这只是排版偏好：前身那一行若在该时点仍被占用，自动退回首次适配，绝不为了对齐而制造重叠。
  几条断点都对应真实的并立——李存勖 923 年四月称帝而朱友贞 十一月方死，石敬瑭 936 年立国
  而后唐 存至 937 年，隋皇泰主据洛阳至 619 年而唐已于 618 年建国——把它们排在不同行是史实，不是缺陷。
  （加了这层偏好后泳道数不升反降：默认 8→7，含王 11→9。）

- **底带由「实际有君主在位」决定，不回退到朝代元数据的年份。** 元数据只精确到年：
  曹魏记作「220」即 220 年 1 月，而汉献帝实际禅位在 220 年 11 月；若以元数据取值，
  两朝会凭空重叠十一个月，接续关系便永远落不到同一行。头尾若真有一年以上无主，
  由「空档审计」单独列出，不靠底带掩盖。
- **以朝代而非皇帝为泳道单元。** 若一行一位皇帝，每个名字要占约 80px 固定宽度；
  实测即使放大到 20px/年仍需 12 行以上（密集期短祚之君扎堆，标签互相挤开）。
  改为朝代长带后只需 8–11 行，且长带本身有足够宽度容纳名称，皇帝以带内分段呈现，
  段间以 2px 底色留缝分隔（而非描边）。
- **标签吸附。** 朝代名与时代名在横向滚动时贴附视口左缘，但不越出自身区间，
  因此任何时刻都能读出「现在看的是哪一朝、哪个时代」。仅当区间跨过视口左缘时才吸附，
  避免同屏的两个时代双双挤到左缘压字。
- **假重叠就地挤压，不分层。** 同朝代内「前帝崩」与「后帝即位」常落在同一个月，
  史料精确到月即产生名义上的重叠：实测 100 处同朝代内重叠中 **95 处不足 0.25 年**
  （康熙／雍正 0.01 年、晋武帝／晋惠帝 0.00 年）。若一有重叠就另起一层，
  整条辽带会被这些假重叠劈成两行。现改为：0.5 年以内的重叠就地挤压——交界取中点、
  两段各退一半，仍并排同一行，靠 2px 底色缝分隔；只有真正并立称帝者才分层错开，
  当前仅 **3 例**（南齐东昏侯／和帝分据建康与江陵、闽景宗／天德帝分据福州与建州、
  南明绍武／永历同时在广州与肇庆称帝）。绘图宽度因此可能比真实在位期短几个月，
  **悬停与数据表给出的始终是真实日期**。
- **不为十几像素挤出纵向滚动条。** 泳道数 ≤10 时不设高度上限并关闭纵向滚动
  （否则横向滚动条占去的十几像素会逼出一条只能滚 11px 的纵向滚动条）；
  超过 10 道时才限高到 10 行，此时的滚动条对应整整一行，是有意义的。

配色可切「按具体朝代」或「按大一统 / 分裂」。按朝代时用**区间图着色**：时间上重叠的政权必为异色，
不重叠的复用槽位（唐与明同为槽 1 不会造成混淆），结果只依赖朝代常量、与过滤器无关——
筛选不会让幸存者改色。并存政权最多 11 个而分类色板只有 8 槽，故 4 个边缘割据政权折入中性灰；
取色优先级按 `tier`（正统序列优先），以免后晋、后汉这类五代主干变灰。每条带都直接标注朝代名，
颜色只是辅助通道，不承担唯一识别职责。

## 空档审计：把可视化当质检工具

横向泳道视图顺带提供了一个意外好用的数据质检信号：**朝代长带上任何悬空的头、尾或中段，
都意味着那段年份没有在位君主的记录**。原因只有三种，应用内的「空档审计」一节把三者逐条列清：

1. **该君主称帝前已掌权**（本库 `a` 记的是称帝日，`r` 记实际掌权日）。
   石勒 319 年称赵王、330 年才称帝；忽必烈 1260 年即汗位、1271 年才建国号元；
   皇太极 1626 年即汗位、1636 年才称帝。共 14 处。这类空档现已在泳道图中
   以**半高浅色段**画出，不再凭空空一截。
2. **史上确实虚位**：永嘉之乱（311–313 洛阳陷后无天子）、大蒙古国的三次监国／称制
   （拖雷监国、乃马真后称制、海迷失后称制）、辽太祖崩后述律后称制、
   侯景之乱平定至萧绎即位。已逐条注明。
3. **漏收君主或日期有误** —— 需要回溯史料。

第三类正是这张表的价值所在。首轮审计查出并已修正：

| 问题 | 原因 | 修正 |
|---|---|---|
| 唐 826–827 年凭空一段空缺 | 敬宗卒于宝历二年十二月，换算公历应入 **827 年 1 月**，原记为 826 | 卒年改 827-01-09，文宗即位改 827-01 |
| 前燕带首空悬 16 年 | 漏收开国之君慕容皝（337 称燕王） | 补入，并为慕容儁补记 348 年嗣位 |
| 北凉带首空悬 4.5 年 | 漏收开国之君段业（397–401） | 补入 |
| 前凉带首尾共空悬 73 年 | 张氏九主中仅张祚称帝，其余八人未收 | 按吴越钱氏同例全部补入 |
| 吴 920–927 年空缺 | 杨溥 920 年已嗣吴王位，927 年才称帝 | 补记实际掌权日 |
| 唐睿宗与武则天「重叠」14 年 | 睿宗两次在位被记成一段，跨越整个武周 | 改记两段；中宗漏记的 705–710 年复辟期一并补上 |

修正后**「待核查」归零**，收录君主由 350 增至 360。审计针对完整数据集运行，不受过滤器影响。

## 跨文明扩展：Wikidata 管线与对账

管线已跑通：奥斯曼、拜占庭、日本天皇、日本幕府四份名册入库（251 位），
中国库与 Wikidata 全量对账。

### 为什么是「骨架 + 人工补关键项」

实测 Wikidata 的字段覆盖率（拜占庭 143 人、日本 128 人、奥斯曼 46 人）：

| 字段 | 覆盖率 | 结论 |
|---|---|---|
| 生卒日期 | ~95%，多精确到日 | **直接可用**，比手录可靠 |
| 在位起讫 | ~84% | **可用**，缺的正是僭称者与逊位后的族长 |
| 死亡方式（P1196） | **~40%** | **不足以支撑结论**，须人工补齐 |

加上 P509（死因）、P157（凶手）几乎无增益——三者高度重叠。故管线只抓骨架，
`violent` 一栏人工判定，但每条锚定 QID，可核可回馈。取值词表本身干净好用：
natural causes / homicide / capital punishment / death in battle / suicide，可直接映射到本库 0–6 编码。

`tools/fetch_wikidata.py` 抓取后落盘为 JSON 并提交进仓库——站点运行时不访问网络，
没有 CORS 与限流问题，且结果可复现。Wikidata 为 CC0，转发无许可负担。

### 三个必须处理的坑

- **限定词用 `pqv:` 而非 `psv:`**。`psv:` 是语句主值前缀，用来抓 P39 的起讫限定词会**静默返回零行**，
  不报错。脚本因此加了「零行即拒绝写入」的护栏，以免用空文件覆盖好数据。
- **历法**。Wikidata 对 1582 年前用儒略历存储（calendarmodel Q1985786），
  而 WDQS 的 `wikibase:timeValue` 会换算成前推格里历——同一个唐太宗，实体 API 给 649-07-10，
  SPARQL 给 649-07-13。中文史料用儒略历口径，故对账取实体 API 原值。
- **名册需策展**。P39 把「王朝覆灭后的家族名誉族长」也算在位，奥斯曼因此多出 1973–1983 两位。
  按 `end_year` 裁去后为 **36 位**，与传世谱系完全吻合。

WDQS 期间处于降级状态（429 限流至 1 req/min，继而 502），故对账改走 `wbgetentities`
实体 API——另一套服务，且做 diff 本就不需要 Wikidata 枚举中国皇帝，名册本库自有。

### 对账结果：360 条 × Wikidata

命中 282/360（78%，未命中多为十六国、十国小政权，或通称与 zhwiki 条目名不一致）。

- **死亡方式：74 处一致，1 处冲突** —— 这是本库最关键的变量，交叉验证结果极好。
- **年份：20 处不一致**（约 560 次比对），其中大半是 ±1 年的阴阳历跨年问题
  （如唐代宗生于开元十四年十二月，换算公历已入次年 1 月）——与此前查出的唐敬宗卒年同类。

差异是双向的。经逐条核对，**以下三处是 Wikidata 有误、本库正确**：

| 条目 | Wikidata | 史实 |
|---|---|---|
| [Q7361](https://www.wikidata.org/wiki/Q7361) 晋怀帝 | 生 300 | **284**（300 实为晋愍帝生年） |
| [Q10011](https://www.wikidata.org/wiki/Q10011) 明世宗（嘉靖） | homicide | 病死；疑与 1542 年壬寅宫变（未遂）混淆 |
| [Q7419](https://www.wikidata.org/wiki/Q7419) 隋炀帝 | 卒 617 | **618-04-11**，江都兵变 |

奥斯曼一侧亦查出一处：[Q165983](https://www.wikidata.org/wiki/Q165983) 英文标签误作 “Selim i”，
而其中文标签「巴耶济德二世」与生卒、在位均正确——仅英文标签有误。

完整报告见 [`data/china-wikidata-diff.md`](data/china-wikidata-diff.md)，由 `tools/diff_china.py` 生成，可重跑。

### 已接入比较视图（`#civ`）：四个政体、五份名册

| 政体 | 君主数 | 非正常死亡 | 生前失位 | 登基后中位存活 | 平均享年 |
|---|---|---|---|---|---|
| 中国 | 347 | 40% | 31% | 8.9 年 | 40.2 |
| 拜占庭 | 82 | 26% | 34% | 10.6 年 | 49.9 |
| 奥斯曼 | 36 | 17% | 39% | 16.2 年 | 51.5 |
| 日本幕府 | 39 | 13% | 51% | 18.0 年 | 41.9 |
| 日本天皇 | 94 | **4%** | **70%** | 22.3 年 | 45.6 |

各文明登基后生存差异 Log-rank χ² = 49.4，df = 4，p < 0.0001。

**三列同时单调**：失位率升 → 暴力率降 → 中位存活升，五个政体的秩相关是完美的 ±1。
这不是巧合能轻易造出的形状，也正是「政治结构 → 统治风险」这条链要说的话。

**「生前失位」取代了「被废黜」。** 后者跨文明不可比：日本的譲位是制度常态，奥斯曼的废立
有乌理玛法特瓦的正式程序，中国则多为政变所迫——压成同一个 0/1 变量等于混淆「制度化交班」
与「政变夺位」。改用可机械推导的口径：**王位终于身死之前**，不问自愿与否，各文明定义完全一致。
自愿与被迫之别，交给它与非正常死亡率的**组合**去体现：

> 日本天皇失位率 70% 而暴力率仅 4%——换人极频繁，却几乎不流血，交班已被制度完全吸收；
> 中国失位率 30% 而暴力率 42%——换得少，但换的时候多半要死人。
> 这正是「政治结构 → 统治风险」想捕捉的东西。

应用里第一张图就是这个二维散点（横轴失位率、纵轴暴力率），比任何单一指标都直观。

**年代混杂：四组比较里三组挺住了，一组翻转。** 各文明年代分布不同，故每组都同时给出
全时段与同期对照，翻转者自动标注并弹警示：

| 对照 | 全时段 | 同期对照 | 判断 |
|---|---|---|---|
| 中国 vs 拜占庭 | 42% vs 26%，p=0.008 | 395–1450：45% vs 26%，p=0.003 | **挺住**（且更强） |
| 中国 vs 日本天皇 | 42% vs 4%，p<0.0001 | 508–1913：37% vs 4%，p<0.0001 | **挺住** |
| 中国 vs 日本幕府 | 42% vs 13%，p=0.0005 | 1192–1867：32% vs 13%，p=0.028 | **挺住** |
| 中国 vs 奥斯曼 | 42% vs 17%，p=0.004 | 1299–1919：27% vs 17%，p=0.258 | **翻转**，以同期为准 |

### 天皇是吉祥物——那就把掌权的将军也抓来比

天皇长期不掌实权，以其代表「日本君主的风险」有失真之虞：4% 究竟是「日本文化不弑君」，
还是「不掌权者不被杀」？这个反驳可以直接检验——把 1185–1868 年真正执政的**征夷大将军**
（Wikidata `Q131767`，39 位）单列一份名册即可。

| 同国同代对照，限于幕府存续期 1192–1867 | 非正常死亡 |
|---|---|
| 掌权的将军 | **13%（5/39）** |
| 虚位的天皇 | **0%（0/41）** |
| | z = 2.37，p = 0.018 |

这是全节最干净的一组：年代与文化都被固定住，唯一变动的是「谁真正掌权」。
天皇一侧四位非正常死亡者（崇峻 592、弘文 672、淳仁 765、安德 1185）**全部早于 1192 年**——
实权移交幕府之后，天皇的暴力死亡精确地归零，而风险随实权一起转移到了将军身上。

**但权力与风险并非单调。** 将军按家系分段：

| 家系 | 非正常死亡 | 实际权力状况 |
|---|---|---|
| 源氏（1192–1219） | **2/3** | 真正掌权，与御家人及北条氏角力 |
| 摂家・宮将军（1226–1333） | 1/6 | 自身也是北条执权的傀儡 |
| 足利（1338–1573） | 2/15 | 权威时强时弱，末期形同虚设 |
| 德川（1603–1868） | **0/15** | 权力最大，且制度化最彻底 |

权力最大的德川反而最安全。可见致命的不是权力本身，而是**权力有争议**——
这与本库中国一侧的发现同调：非正常死亡集中在分裂期与继承规则失效之时，而非皇权最盛之时。
（护良亲王属建武政权，持征夷大将军号，计入将军名册。）

### 名册策展与已知偏倚

- **拜占庭**：起点取 395 年东西罗马永久分治（Wikidata 自 337 年起算，会纳入仍统治全罗马的
  君士坦提乌斯二世、瓦伦斯等）；另排除 **23 位**皇后配偶与共治幼帝——Wikidata 的 P39
  「拜占庭皇帝」把欧多西亚、维丽娜、克里斯托弗·勒卡潘诺斯等一并收入，他们从未临朝。
  110 → 82。
- **日本天皇**：剔除继体天皇（507）以前的传说时代 **28 位**，其纪年不可信（神武上溯前 660 年，
  照收会把「在位八十年、享年百余岁」的神话数据混进统计）。122 → 94。
- **日本幕府**：取 1185–1868 幕府存续期，39 位，含建武政权的护良亲王。
- **奥斯曼**：裁去 1922 年王朝覆灭后的两位家族名誉族长。38 → 36。
- **拜占庭的 26% 可能偏低**：该朝惯用的政治惩罚是刺瞎与剃度出家而非处死，本库将
  「被废刺瞎、其后病殁」记为正常死亡。若把致残一并计入，比例会明显上升。
- 「生前失位」在仅精确到年且同年者上无法区分「死于任上」与「当年被废后卒」，保守记 0，
  故该指标是**下界**。
- **将军 vs 天皇那组 0/41 是零计数格**，两比例 z 检验在此类格上偏乐观，宜作方向性证据读。
- **同期对照窗口按小数年向外取整显示**（仅知年份者按年中估算），故 1192.5–1866.5 显示为 1192–1867。

#### 一处已修正的口径 bug：日期精度与字典序

「生前失位」原先直接比较 ISO 日期串。但两端精度常不一致——退位只知年、卒日精确到日——
而 `"1616" < "1616-06-01"` 在字典序下**恒真**（前缀关系）。结果德川家康一类「同年退位、同年身故」
全被误判为失位，幕府一度显示 **39/39（100%）**，这个不可能的整数暴露了问题。
现按两者**较粗**的精度逐段比较（见 `tools/build_civ.py: lost_throne`）。
受影响的已公布数字：拜占庭失位率 44% → **34%**，奥斯曼 56% → **39%**。
中国一侧不走日期比较——本库有独立的退位日字段（`z`），有值即失位，107/360 = 30%，精确无歧义。

### 下一步

法兰西、神圣罗马、俄罗斯、英格兰同处一个区间，schema 已通用，随时可加；
但边际信息量低于已有的五份名册。更值得做的是沿「将军 vs 天皇」这条路继续走——
**把「实权持有者」而非「名义君主」作为分析单位**：中国的权臣与摄政、拜占庭的共治皇帝、
奥斯曼的大维齐尔，都能构成同类对照。此外把「致残」单独建模（拜占庭的刺瞎、中国的幽禁），
以及为各文明补上继承法类型（长子继承／幼子继承／推举／无成法）作为解释变量——
那才是「政治结构」的真正操作化。

## 统计方法

| 方法 | 说明 |
|---|---|
| Kaplan–Meier | 支持左截断（延迟进入）；Greenwood 方差 + log-log 置信带 |
| Log-rank | k 组，支持左截断 |
| Cox 比例风险 | Efron 结法、`(start, stop]` 区间、Newton–Raphson + 步长折半 |
| PH 诊断 | Schoenfeld 残差与时间秩的相关性检验 |
| 竞争风险 | Aalen–Johansen 分因累积发生率 |
| 其他 | Mann–Whitney U（含并列校正）、Welch t、Spearman ρ、最小二乘、可复现自助法 |

**两条时间轴**：

- **登基后年数（默认）** — 每人自 t=0 进入，无截断问题。回答「坐上龙椅之后还能活多久」。
  退位者可选在退位时删失，以隔离「在皇位上」的风险。
- **年龄（左截断）** — 每人自登基年龄进入风险集，校正「必须活到即位才会进入样本」的选择偏倚，
  并默认以满 15 岁为条件起点：襁褓即位者（汉殇帝、周静帝）会让低龄段的风险集只剩一两人，
  一次死亡即把曲线打掉一半。

**删失**：明惠帝朱允炆 1402 年失踪、卒年不可考，按删失处理（`xc` 字段），既不剔除也不臆测。

**风险集退化的硬拦截。** 左截断下若某个事件时点的风险集只剩一人，其死亡会把生存概率 S 打到 0，
此后所有增量都是 `S×d/n = 0`——余下样本对曲线不再有任何贡献，KM 平在 0，累积发生率被永久冻结。
估计量没算错，但画出来的东西毫无意义。实例：年龄尺度关掉条件起点时，大一统组在 1.6 岁处
风险集只剩汉冲帝一人，他一死，其后 92 例死亡（占 94 例的 **98%**，含全部非正常死亡）
全部失效，图上于是显示「100% 病死、0% 被杀」——纯属退化，不是史实。

因此 KM 与竞争风险两张图都会跑 `riskSetDiagnostics()`：**仅当塌陷之后确实还有事件被吞掉时**
（`eventsAfter > 0`——S 在最后一个死亡处归零是曲线的正常终点，不算退化）
弹出红框警示，点名塌陷时刻、当时风险集里剩下谁、有多少事件被吞，
把该分面降到 40% 不透明度以免被误读为正常结果，并给一个「设回满 15 岁」的一键修复。
默认设置下不触发；样本被筛到很小时（如仅丹药组 n=18）会如实触发。

## 主要发现（默认筛选，n = 347）

这些数字随过滤器实时重算。**大理段氏 22 位入库后**（937–1254，与两宋相始终），
各数字略有稀释——总 HR 0.71→0.75（0.59–0.96，p = 0.024）、非正常死亡 42%→40%、
中国 vs 拜占庭同期对照 43% vs 26%（p = 0.007）——方向与显著性全部不变；
下述各条为大理入库前的记录，精确数字以应用内实时计算为准。
大理自身是个值得单看的案例：十位君主**禅位为僧**、逊位常态化，
是「高失位＋低暴力」的又一例，与日本天皇的制度化交班同型；
段正严（段誉的原型）逊位后活到 93 岁，把全库最长寿从乾隆（87）手中接了过去。

1. **平均享年读不出统一与分裂的差别，生存分析读得出。**
   大一统 40.0 岁 vs 分裂 40.0 岁（Welch p = 0.996）——几乎完全相同。
   但登基后中位存活 14.5 年 vs 7.3 年；控制登基年龄后
   **HR = 0.71（95% CI 0.55–0.92，p = 0.008）**。
   原因：大一统皇帝平均 22.9 岁即位，分裂时期 27.6 岁——观察起点不同，
   「平均享年」把「何时登基」与「登基后的风险」混成了一个数。

2. **统一的优势几乎全部落在暴力死亡一侧。** 非正常死亡占比 23.4% vs 49.1%。
   分因风险模型（控制登基年龄）：非正常死亡 **HR = 0.40（0.25–0.66，p = 0.0003）**；
   正常死亡 HR = 0.84（0.62–1.14，p = 0.254）。
   统一不会让人更不容易生病，只会让人更不容易被杀——这正是 H5 所预言的模式。

3. **丹药组没有显示出显著风险**（n = 17，调整后 HR = 1.21，95% CI 0.73–2.02）。
   样本太小，且存在强烈的反向因果：服丹多见于长期在位、活到中老年的皇帝，
   而「服丹」一事本身往往因暴卒才被史官追记。

4. **DSI 与王朝平均享年正相关**（王朝层面 n = 46，Spearman ρ = 0.42，p = 0.004），
   但 DSI ＝ 国祚 ÷ 皇帝人数，与在位时长在算术上同源，这一相关性存在严重内生性，
   不能读作「稳定的王朝让皇帝更长寿」。

## 已知局限

- **不是随机样本。** 帝王是极端选择性的人群，其寿命不代表同时代人口。
- **缺失非随机。** 46 位（13%）生年失载，集中于十六国、闽、南汉等割据政权的短祚之君，
  而这些人恰恰更可能早夭——凡以「平均享年」为指标的结论都被系统性抬高。
  应用内按时代披露缺失率。
- **不朽时间偏倚。** 「亲历战争」「遭遇政变」「首都陷落」都发生在在位途中，
  本库按「一生中是否发生过」编码为时间固定变量，而必须先活得够久才有机会经历它们，
  故这类变量的 HR 被系统性拉低。严格做法需改写为时变协变量，需逐位皇帝的事件时点，尚未采集。
- **年龄尺度的拟独立假定不成立。** 幼年即位者多出于外戚、宦官擅权之局，其后被弑概率本就更高，
  故进入时间与死亡时间不独立。因此以登基后尺度为主分析。
- **「非正常死亡」不能作为解释寿命的自变量**——它是结局的一部分。可检验的形式是分因累积发生率。
- **史料本身。** 年龄按公历实足年龄推算，与中文「虚岁」相差约 1 岁；仅有年份者按年中估算，误差 ±1 岁。
  本库属研究原型，未逐条附注出处，**正式引用前请回溯核校**。

## 配色

沿用已验证的分类色板，语义槽位在全应用中固定：**蓝＝大一统，橙＝分裂**，绝不因排序或筛选而改色。
`tools/validate.html` 可在浏览器内重跑六项检查（浅/深两套主题）。
其所加载的 `tools/validate_palette.js` 并非本项目原创，来自 Claude Code 内置的 dataviz 技能包
（`scripts/validate_palette.js`），此处原样收录仅为使校验可复现，著作权归原作者：

- 二分（槽 1–2）、三分（槽 1–3）：`--pairs all` 全过；六分（槽 1–6）：adjacent 全过。
- 浅色主题下 aqua / yellow / magenta 低于 3:1，触发 relief 规则——每张图都配有直接标注与表格视图。

## 移动端

改造前在 375×812 实测的四项硬伤，以及各自的处理：

| 症状 | 改造前 | 改造后 |
|---|---|---|
| 吸顶过滤器条 | 422 px（**占屏 52%**），常驻遮挡 | **45 px（6%）**，收起态只留摘要 |
| 图表画布 | viewBox 1080 压进 289 px（**0.27×**，11 px 刻度实际 3 px） | 全部 **1.0×**，字号不再随画布缩放 |
| 锚点跳转 | `scroll-padding-top` 写死 140 px | 由 `--filters-h` 实测写回，桌面 143 / 手机 57 |
| 页首到第一张图 | 1907 px | **1182 px** |

三处非显而易见的设计决定：

- **展开的筛选面板是绝对定位的浮层，不撑高吸顶条**。若让面板把 `.filters` 顶高，
  吸顶区又会占满半屏，`scroll-padding-top` 也得跟着开合变化——等于没解决。
  做成浮层后吸顶高度恒为 45 px，锚点偏移是个常量。
- **画布宽度的下限由边距自动推出，而非逐图手调**：净绘图区不足 180 px 就不再收窄，
  改由 `.chart-host` 横向滚动。于是 Cox 森林图（左边距 250 px 放变量名）会被判定为放不下，
  进而切到「变量名与 HR 并排在上、CI 线另起一行」的两行式布局；
  而 KM 曲线（左边距 56 px）直接铺进 375 px。
- **触摸端的提示框要单独处理**：`pointerenter/pointerleave` 在触屏上对应「手指按下 / 抬起」，
  沿用鼠标那套的话，提示只在手指压着的那一瞬存在，而那一瞬它正好被手指遮住。
  改为按下即显示、抬起不收，点别处才收，并把气泡挪到触点上方。

长节的「跳过本节」浮动按钮只在窄屏、且**本节超过 1.5 屏、还剩不止一屏**时出现——
否则它就是块常驻的挡板。当前触发它的是跨文明比较（2.8 屏）、H1–H5（2.4 屏）与 Cox（1.6 屏）。
按钮文案带出下一节的名字，跳转后落在距顶 `--filters-h + 12px` 处，标题不会被吸顶条压住。

筛选面板的展开状态存在全局状态 `S.filtersOpen` 而非 DOM 上：任一 chip 变动都会触发全量
`render()` 把过滤器重建一遍，挂在节点上的状态会随之丢失，表现为「点一下筛选面板就自己收起来」。
